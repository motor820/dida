# Dida 多端同步方案（历史设计）

适用：个人使用，Mac Apple Silicon 桌面端 + 安卓手机 + 需要登录的网页版。
公网地址：https://dida.aiking.net:888/
此文保留最初设计及验收目标，不能作为当前实现承诺。2026-11-04：网页、Mac 与自建同步已经交付；用户确认 M1 测试通过；安卓暂缓。实际能力见 [使用说明](WEB-MACOS.md)，开发安排见 [TODO](../TODO.md)。原方案中的刷新令牌、90 天删除清理等细节不代表已实现；公历重复实例生成现已交付，当前实现以代码和安全报告为准。

## 当前实现与原方案的差异（2026-11-05）

网页与 Mac 同步、公历重复下一期、MCP 和 Rona 已交付；安卓、后台系统通知仍未交付。当前为可撤销 opaque session，而非原提案的刷新令牌方案；Mac 使用原子 sync_local_state 保存业务与队列，网页使用 IndexedDB。以下编号章节保留原设计目标，不当作 API 契约。

## 1. 推荐架构

Mac 和安卓各保留本地 SQLite；客户端所有增删改先在本地完成，同时在同一事务中写入待同步队列。联网后经 HTTPS 将增量提交至自建 API，再拉取其他设备变更。
服务端使用 Rust + Axum + SQLite，直接在本机编译运行，由 systemd 用户级服务管理，不使用 Docker。服务端 SQLite 使用 WAL、事务及受控单写入，适合当前单人多设备范围；不新增 Redis 或独立数据库服务。
客户端共用现有 React 界面与 Rust 业务模型，提取独立于 Tauri 窗口的同步模块。

流向：Mac 本地库 ⇄ HTTPS API / 服务端库 ⇄ 安卓本地库。
服务端不是同步原始 SQLite 文件，而是同步任务、清单、标签等记录的变更。

## 2. 同步范围

第一版覆盖任务标题、内容、完成状态、优先级、截止时间、子任务、所属清单、清单及任务排序、标签与父子标签、标签关联、提醒及重复规则、回收站及恢复。
智能清单（今天/最近七天/已完成等）由本地规则计算，不同步整份查询结果。
窗口大小、侧栏宽度、设备通知权限、登录凭证等保留为设备设置。
第一版不增加多人协作、附件、日历账号集成或跨平台系统推送服务。

## 3. 协议和一致性

- 每个设备拥有 device_id；每次操作拥有唯一 operation_id，以便网络重试去重。
- 每条实体有服务端版本号；每个账户有严格递增的服务端变更序号。客户端保存已确认游标，不依赖设备时钟判断新旧。
- 修改只提交变化字段与 base_version，避免上传整条旧记录覆盖另一设备的修改。
- API 在事务中校验归属、引用关系、版本并持久化数据、去重记录与变更日志；同一事务内成功后才确认操作。
- 本地业务变更和待同步操作也必须同一事务保存。失败不丢队列，自动退避重试；拉取的远端变更不再次生成待上传操作。
- 每次拉取使用固定的服务端水位和分页游标；全部落库成功后才推进游标。
- 需要关联实体一起变化的操作按事务处理，例如父任务及子任务完成、删除清单与其任务的既定删除行为。先同步清单/标签，再同步依赖它们的任务和关联关系。
- 重复任务生成使用可去重的规则实例标识，避免两端各生成一份下一次任务。

冲突规则：
1. 两端修改不同字段时自动合并。
2. 同一字段冲突采用最后修改者优先（LWW），以服务器校准后的操作修改时间比较，不显示冲突选择界面，不额外保留供人工选择的冲突副本。实际较旧的离线修改不能仅因较晚上传而获胜。
3. 客户端记录毫秒级 UTC 修改时间、逻辑计数和操作 ID；联网时校准服务器时差，使用混合逻辑时间保证设备操作顺序，时间完全相同时按稳定规则决胜，避免来回覆盖。所有客户端应用服务端返回的最终结果；设备时间明显异常时先校正后提交。物理时钟误差下无法绝对还原现实先后，不能将时间校准描述为绝对保证。
4. 删除和恢复也带操作时间并参与同样比较；旧编辑不得让较新的删除复活。已永久删除的 ID 不作为普通更新对象恢复，需要另建记录。删除标记初期保留 90 天；超期离线设备先重建服务器快照，旧队列按设备同步代次处理，不盲目重放。

## 4. 触发与用户体验

启动、切回前台、网络恢复时立即同步；编辑结束后约 1–2 秒合并提交；前台每 10–15 秒拉取一次其他设备变更。具体间隔可配置，作为目标而非网络延迟保证。
界面显示：已同步/待上传数量/离线/同步失败与重试，并提供手动同步入口；不提供需要用户选择的冲突弹窗。
安卓后台同步遵循系统调度，不能承诺应用退出或被系统终止后仍秒级同步；下次打开必须主动补齐。
提醒时间和规则参与同步；系统通知由各设备本地调度。安卓锁屏提醒需原生通知、权限及省电策略适配，不能复用现有网页定时器来承诺可靠提醒。已排定的本机提醒不能保证在离线时立即获知另一设备上的取消。

## 5. 账号和公网部署

- 单个私人账号，多设备登录，Mac、安卓和网页版共用同一账号密码；关闭公开注册。
- 网页版第一版即接入统一账号和同步，未登录时只展示登录页，API 同样验证登录态；不能只用前端密码遮罩。每台设备使用独立会话，设备退出不影响其他设备，账户改密后撤销旧会话。
- 密码使用 Argon2id 哈希；短时访问令牌、可轮换刷新凭证、退出登录与设备撤销功能。Mac 和安卓凭证进入系统安全存储，不写入仓库。
- 按账户校验每条数据，增加登录限速和 API 请求上限；日志不记录密码、令牌和完整任务正文。
- 不创建 Docker 容器或 1Panel 编排。源码继续位于本机仓库，服务名 dida-sync.service，unit 路径 ~/.config/systemd/user/dida-sync.service。
- 可执行文件安装到 ~/dida/runtime/；配置位于 ~/dida/private/，数据库和备份位于 ~/dida/data/，与源码分开。
- 启用 systemctl --user enable 和用户 linger，使开机后无需交互登录即可运行；配置崩溃重启，日志使用 journalctl --user。
- 服务计划仅监听 127.0.0.1:1430，实施前再核实端口；同时提供已构建网页和 /api/v1 接口。OpenResty 通过现有公网 888 → 本机 443 映射提供服务，不直接暴露后端端口。
- 1Panel 网站：dida.aiking.net。复用既有 Cloudflare DNS 验证账号申请独立 Let's Encrypt 证书，启用自动续签。
- 所有跳转、公开 URL 和请求头保留外网 :888。
- 用户已完成域名解析。实施时核实指向现有公网入口且为“仅 DNS（灰云）”；服务端和 TLS 配置由部署阶段完成。
- /api/v1/auth/login、/api/v1/auth/refresh、/api/v1/sync/push、/api/v1/sync/pull、/api/v1/sync/bootstrap、/api/v1/devices、/healthz 为拟定接口。
- 网页使用同域前端及 API，登录使用 HttpOnly、Secure、SameSite 会话 Cookie，配合来源校验/CSRF 防护；按账号隔离 IndexedDB 缓存。退出登录清除当前浏览器的任务缓存与本地队列，避免共享电脑遗留数据。
- 网页采用同一套密码；原生客户端凭证进入系统安全存储。密码只上传到认证接口，不作为同步密钥或直接存入 localStorage。

## 6. 数据迁移与备份

实施前备份本地 SQLite 和浏览器现有数据。增加正式数据库迁移版本，保留已有 ID 与关联；补齐清单/标签版本和删除标记。
统一运行环境识别并验证 Mac/安卓确实走本地 SQLite。
首次接入由一台选定设备导入现有数据；其他设备通过快照初始化，避免分别初始化产生重复默认清单。浏览器现有任务通过一次性导出导入迁移，不自动混入。
服务端每日使用 SQLite 在线备份，保留最近 14 份；部署配置和密钥另存受限备份。单机备份仅能防误操作，另留向既有备份存储复制的配置入口。
升级客户端前自动备份旧库；服务器数据恢复后更换同步代次，迫使设备重新建立快照并审查未上传操作。

## 7. 实施顺序与交付

准备阶段：专项验证运行环境识别、智能清单初始化及外键级联行为；修复本地数据持久化问题，避免同步建立在不可靠的本地存储行为上。
第一阶段：服务端、数据库迁移、同步协议和公网 API；实现登录、去重、增量、冲突、删除及备份。
第二阶段：Mac 与网页版接入统一账号、本地队列和同步，提供服务地址/同步状态，构建新的 Apple Silicon 安装包；网页版同域部署并强制登录。
第三阶段：初始化 Tauri Android 工程，适配手机布局、网络恢复与生命周期，构建签名 APK。安卓签名密钥持久保管，后续更新保持一致。
第四阶段：安卓通知与提醒适配，并完成三端端到端验收。

安卓构建所需 SDK/NDK 与 Rust 目标使用官方工具链，安装包签名使用本项目独立 Android 密钥，不需要苹果开发者证书。
GitHub Actions 分别生成 Mac 和安卓构建产物，用户自行下载；源码改动在 motor820/dida 独立分支实现和验收。

## 8. 验收标准

1. Mac 新建任务，安卓前台自动出现；安卓完成后 Mac 显示完成。
2. 两端分别离线修改不同字段，恢复网络后都保留。
3. 同字段冲突自动使用较新的修改时间，无人工确认；离线旧修改晚上传不得覆盖在线新修改，时间相同的结果稳定一致。
4. 反复断网、重复上传、请求响应丢失不产生重复任务或重复周期实例。
5. 回收站、恢复、永久删除和超长期离线设备不会导致任务复活。
6. 任务、清单、标签、子任务、关联和排序在两端一致。
7. 服务重启、客户端重启后，待上传操作和同步游标仍有效。
8. 新设备登录能从快照恢复；撤销设备后旧凭证不能继续访问。
9. 首次数据迁移与服务端备份恢复都实际演练。
10. 安卓真实手机验证移动网络访问、前后台切换及本地提醒行为；不将 CI 编译通过当作真机验证。
11. 网页、Mac、安卓用同一账号密码访问同一数据；未认证请求、过期会话和改密前会话均不能读取任务。
12. 服务器重启且未登录桌面时用户服务自动运行，网页和 API 可访问。

## 原始推荐默认值（历史记录）

采用单用户、Mac + 安卓 + 网页、离线可用方案；三个客户端共用账号密码，网页必须登录；服务器 Rust + SQLite，systemd 用户服务开机启动，不使用 Docker；冲突按校准后的修改时间自动取最新，无人工选择；API 地址 https://dida.aiking.net:888，域名解析已由用户完成。
上述为原始方案。当前网页和 macOS 0.2 已包含同步能力；安卓不在本次交付范围。
